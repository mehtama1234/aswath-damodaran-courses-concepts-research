Concept

Real options

Meaning. Managerial flexibility embedded in projects: the option to expand, abandon, delay, or adapt as uncertainty resolves.

Why it matters. Real options matter when static NPV misses the value of learning and future choice.

How Damodaran develops it. The Celsius and post-mortem material uses real options to show when uncertainty can create value rather than merely risk.

Common mistakes

  • Calling every uncertain project an option.
  • Double-counting option value already embedded in cash-flow forecasts.

Worked example

A pharmaceutical firm invests $100M in a Phase 1 drug trial expected to have NPV of -$80M (high clinical failure risk). Traditional NPV says reject. But embedded in the trial is a real option: if it succeeds at the 30% clinical rate, the firm has the right (but not obligation) to spend $300M more on Phase 2/3, where full development could yield $2B in value. Option value calculation: 0.30 × ($2B - $300M) = 0.30 × $1.7B = $510M value of the success case. Phase 1 cost ($100M) buys entry to an option worth $510M. Net: $410M. Real-option NPV = -$80M (negative base case) + $510M (option value) = $430M. The project goes from reject to strong accept once you price the embedded option.

Another example: A retailer opens a test store for $2M. NPV of that store alone is negative ($500K loss per year × 5 years = $2.5M loss). But it buys an option to expand to 50 stores in the same region (option value $30M) or abandon if the market doesn't work (saves $20M in avoided bad expansion). Option value dominates the NPV. Traditional analysis sees losing money. Options analysis sees the value of future choice.

Where the approach breaks

Real-options thinking fails when applied indiscriminately to every uncertain project. Every project has some embedded flexibility, but if you price options for waiting, expanding, and pivoting in every case, you justify everything. The discipline breaks when the option requires exclusivity (you, not competitors, have the right to expand) or when you ignore that competitors also have the option. During the 2010s startup boom, founders used option language to justify losing money indefinitely: "Our negative unit economics buy us the option to achieve scale." But if the unit economics don't improve at scale (the option never pays off), you've just lost money with a sophisticated label. Amazon's AWS is a real option success (cloud betting paid off); most startups' "growth at any cost" bets are not. Another failure: mispricing the exercise cost or the success probability. If you assume a 30% success rate for a drug when historical data shows 15%, option value balloons and justifies wasteful R&D spending. Real-options analysis is powerful but requires honest probability estimates and clear exercise dates. Otherwise, it becomes a theoretical cover for continuing value-destroying projects indefinitely.
